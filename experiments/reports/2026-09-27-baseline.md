# First chronological baseline on the September 27 capture

## Input and split

- Dataset: `6b556515-5156-4181-8a6f-7403fa9078fe`, Parquet schema 2, one
  complete Capture Run.
- Capture UTC interval: 2026-09-27 10:01:25.338 to 2026-09-28 09:03:43.613
  (23 hours, 2 minutes, 18 seconds).
- Quality counters: 3 disconnects, 3 Order Book unavailable intervals, 3 trade
  stream gaps, 0 invalid messages, 450 deduplicated trades.
- The exported market events contain Aster, Binance, and Lighter. No
  Hyperliquid market events are present in this dataset.

Cut points are 60% and 80% of elapsed local receive time. Event membership is
by contiguous Capture Sequence interval, so a later event cannot enter an
earlier split. Each split starts with empty simulator state.

## Baseline

The existing `CrossVenueArbitrageStrategy` was run without parameter tuning on
train and validation. It used the top one level on each side, with the default
simulator settings: 5 bps taker fee per venue, 50 ms order latency, zero added
market-data latency, zero slippage, and a required net edge of 1 bps plus a
1 bps latency buffer. The test set has not been run.

| Split | Orders | Fills | Fees (USD) | Simulated net PnL (USD) | Ending net BTC position |
| --- | ---: | ---: | ---: | ---: | ---: |
| Train | 6 | 6 | 0.0628 | +0.0494 | +0.00029 |
| Validation | 6 | 6 | 0.3008 | +0.1258 | 0 |

Outputs are in ignored local directories `experiments/data/results/day-train-top1`
and `experiments/data/results/day-validation-top1`.

These PnL numbers are **not evidence of executable arbitrage**. The train run
ended with unequal buy and sell fills, leaving directional BTC exposure. The
simulator marks open inventory using its last available book, and its zero
slippage setting is only an assumption. Six fills per split are too few to
estimate a robust return. Before using test for final evaluation, specify how
partial two-leg execution and remaining inventory should be handled, then
re-run train and validation with that policy fixed.
